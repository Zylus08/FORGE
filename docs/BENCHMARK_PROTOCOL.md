# FORGE Benchmark Protocol

## Principles

1. **Isolation** — Each workload × backend combination runs in a **fresh subprocess** to prevent cross-contamination of JIT caches, thread state, and memory allocators.
2. **Warm-up** — Discard the first N iterations (default N = 5) before recording measurements to allow JIT compilation, kernel caching, and OS scheduler stabilization.
3. **Steady-state measurement** — Record M iterations (default M = 50) in the steady-state window.
4. **Clock** — Use `time.perf_counter()` for wall time and `psutil.Process().cpu_times()` for CPU-user time. Never use `time.time()`.
5. **Determinism** — Fix `torch.manual_seed(42)` and `numpy.random.seed(42)` before every run.

## Metric Definitions

| Metric | Unit | Description |
|--------|------|-------------|
| `throughput` | samples/sec | Batch size ÷ median iteration wall time |
| `wall_time_p50` | ms/iter | Median wall time across steady-state iterations |
| `wall_time_p99` | ms/iter | 99th-percentile wall time |
| `cpu_time_p50` | ms/iter | Median CPU-user time |
| `peak_rss_mb` | MB | Peak RSS recorded by psutil during the run |

## Run Procedure

```
for workload in workloads:
    for backend in backends:
        launch subprocess:
            set_num_threads(config.num_threads)
            model, loader = workload.build()
            prepared = backend.prepare(model, config)
            # Warm-up
            for i in range(N_WARMUP):
                backend.train_step(prepared, next(loader))
            # Measure
            times = []
            for i in range(N_MEASURE):
                t0 = perf_counter()
                backend.train_step(prepared, next(loader))
                times.append(perf_counter() - t0)
            record(workload, backend, times)
```

## Result Schema

Results are written as JSON to `benchmarks/results/<run_id>.json`:

```json

  "forge_version": "0.1.0-m1",
  "run_id": "<ISO8601 timestamp>",
  "hardware_profile": "<path to HARDWARE_PROFILE.md>",
  "results": [
    {
      "workload": "resnet18",
      "backend": "torch-eager",

```

## Reporting

Comparative reports are generated by `benchmarks/scripts/compare.py`:

```bash
python benchmarks/scripts/compare.py \
    --baseline benchmarks/results/m1_baseline.json \
    --candidate benchmarks/results/m1_forge.json \
    --out benchmarks/results/m1_comparison.md
```

The report shows speedup ratio, confidence intervals (bootstrap, 1000 resamples), and flags any regression > 2%.

## Anti-Patterns to Avoid

- Do **not** run baseline and candidate in the same process.
- Do **not** average across workloads with different batch sizes.
- Do **not** report throughput from warm-up iterations.
- Do **not** report wall time without also reporting CPU time (they diverge under NUMA effects).
